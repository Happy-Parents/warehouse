# Contract: Internal Modules

Public surface of each foundation module. Feature code imports only these; internals may change.

## `@/db/database`

```ts
import { Database } from '@nozbe/watermelondb';
export const database: Database;      // singleton, adapter jsi: true, schema version 1, no tables
export { schema } from './schema';    // appSchema({ version: 1, tables: [] })
```

Provider: `DatabaseProvider` from `@nozbe/watermelondb/react`, mounted once in `src/app/_layout.tsx` with `database`. Components call `useDatabase()` from the same package.

Adding a table later: bump `schema.version`, add the table to `tables`, add a migration under `src/db/migrations.ts`, add the model class under `src/db/models/` and register it in `modelClasses`.

## `@/api/errors`

```ts
export class ApiError extends Error {
  readonly name: 'ApiError';
  readonly status: number;            // 0 when no HTTP response
  readonly details?: unknown;         // parsed JSON body when available
  constructor(status: number, message: string, details?: unknown);
}
export function isApiError(error: unknown): error is ApiError;
export const normalizeError: BeforeErrorHook;  // ky hook: HTTPError -> ApiError
```

Normalization rules: ky 2 pre-parses the error body into `error.data` before `beforeError` runs (the response stream is already consumed); a JSON body with an `error` or `message` string becomes `message`, otherwise `response.statusText` or `HTTP <status>`; `details` is `error.data`.

## `@/storage/secureStorage`

```ts
export type SecureKey = 'smoke';      // extended by features (e.g. 'accessToken')
export const secureStorage: {
  get(key: SecureKey): Promise<string | null>;
  set(key: SecureKey, value: string): Promise<void>;
  remove(key: SecureKey): Promise<void>;
};
```

`get` resolves `null` when the key is absent; it never throws for absence. Native failures propagate as thrown errors.

## `@/i18n`

```ts
import i18n from 'i18next';
export default i18n;                  // initialised synchronously at import with resources, lng, fallbackLng 'en'
export const SUPPORTED_LANGUAGES: readonly ['uk', 'en'];
export function resolveLanguage(deviceLanguageCode: string | undefined): 'uk' | 'en';
```

`resolveLanguage('uk') === 'uk'`, `resolveLanguage(undefined) === 'uk'`, `resolveLanguage('en' | 'de' | 'pl' ...) === 'en'`. Components use `useTranslation()` from `react-i18next`. Keys are typed; see [data-model.md](../data-model.md#translation-resource).

## `@/components/ui/button`, `@/components/ui/text`

Generated by react-native-reusables. Treat as project-owned source (edit freely), but prefer re-running the CLI with `--overwrite` to pick up upstream fixes.

```tsx
<Button variant="default" size="default" onPress={...}><Text>{t('home.openSettings')}</Text></Button>
```

Variants: `default | destructive | outline | secondary | ghost | link`. Sizes: `default | sm | lg | icon`.

## Routes (`src/app/`)

| File | Path | Title key | Content |
|------|------|-----------|---------|
| `_layout.tsx` | – | – | `SafeAreaProvider` > `DatabaseProvider` > `I18nextProvider` > `ThemeProvider` > `Stack` with `Stack.Screen` entries for `index` and `settings` |
| `index.tsx` | `/` | `home.title` | heading + `Button` wrapping `Link href="/settings"` (or `router.push`) |
| `settings.tsx` | `/settings` | `settings.title` | heading + database diagnostic line |

Navigation back from Settings uses the native stack header back button; no custom back control is implemented.
